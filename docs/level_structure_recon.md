# Reconnaissance Report: Level Structure (MAP_ASSAULT_1)

## 1. Структура експортованих файлів рівня
Під час аналізу директорії `extracted/export/assets/10_FWP_ASSET_MAP_ASSAULT_1` було виявлено, що рівень складається лише з трьох ключових файлів:
- `scripts/assault1_fla/MainTimeline.as`: Точка входу в SWF, яка просто створює новий об'єкт мапи (`this.map = new dmap(0,0)`).
- `scripts/dmap.as`: Порожній клас, що наслідує `flash.display.BitmapData`.
- `images/1_dmap.png`: Єдиний PNG-файл (385 КБ), який містить усю графіку ландшафту.

## 2. Відсутність Tilemap та Об'єктних шарів
Аналіз коду в `world.as` остаточно спростував припущення про використання Tilemap або ієрархії об'єктів (Object Graph/MovieClip Children):
- **Графіка та Колізії**: Ландшафт є єдиним суцільним растровим зображенням (`1_dmap.png`). Фізика та зіткнення працюють за принципом **pixel-perfect collision** (як у грі Worms). Код у `world.as` (рядок 228, 649) використовує метод `this.map_bitmap.getPixel(x, y)` для перевірки, чи є піксель прозорим.
- **Відсутність маркерів**: У файлі рівня немає жодних невидимих маркерів спавну, тригерів чи декоративних шарів.

## 3. Як завантажуються дані рівня (Spawn Points)
Оскільки файл рівня — це просто картинка, всі координати (spawn points) об'єктів та гравців жорстко захардкоджені безпосередньо у класі `world.as`. 
Наприклад, функція `init_assault_coords()` (рядок 1031) створює масив `WORM_ASSAULT_COORDS`, де для `assault1` прописані координати (x, y) для трьох команд:
```actionscript
"assault1":{
   "team1":new Array(805,471,258,167,923,155,22,451,535,308),
   "team2":new Array(650,50),
   "team3":new Array(311,345,620,567,1154,253,169,497,461,221)
}
```
Гра просто завантажує `1_dmap.png` через `Loader.loadBytes()` та розставляє хробаків за цими захардкодженими координатами.

## 4. Висновки щодо формату міграції
- **Phaser Tilemap / Custom JSON Scene**: **НЕ ПОТРІБНІ**. Рівень не є тайл-мапою.
- Спроба конвертувати це в Tilemap буде абсолютно хибною і зламає механіку руйнованого ландшафту.
- **Які дані можна витягти автоматично**: За допомогою простого Regex-скрипта (або AST-парсера) ми можемо витягти всі координати з функцій `init_mission_coords`, `init_assault_coords` тощо з `world.as` та згенерувати чистий `levels_config.json`.
- **Які дані доведеться реконструювати**: Механіку попіксельного руйнування ландшафту. У Phaser 3 для цього доведеться використовувати `CanvasTexture` (або `RenderTexture`), на якому ми будемо "стирати" пікселі (операція `globalCompositeOperation = 'destination-out'`) при вибухах.

## 5. Рекомендований перший Technical Slice
Замість написання Tilemap-парсера (який виявився непотрібним), найбільш обґрунтованим першим кроком міграції тепер є:
1. Написання простого скрипта-екстрактора (наприклад, на Python/Node.js), який прочитає `world.as` і виплюне `coords.json`.
2. Створення мінімальної сцени у **Phaser 3**, яка:
   - Завантажує картинку `1_dmap.png` у CanvasTexture.
   - Малює точки (спавни) поверх картинки, прочитавши їх з `coords.json`.
   - Додає базову логіку гравітації: точка падає вниз, поки колір пікселя під нею прозорий (перевірка `context.getImageData`).
